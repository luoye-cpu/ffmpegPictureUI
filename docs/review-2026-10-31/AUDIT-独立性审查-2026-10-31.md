## 2. 定罪清单（S1–S10，判词先行）

### S1 · 失败作业销毁用户原件 —— **P0**，对撞 ◎

**判词**：主转换路径**直写最终路径**，且命令行第 0 个 token 恒为 `-y`；作业中途失败时，"保留"逻辑留下的是被 `-y` 截空的尸体而不是原件，销毁发生在保留之前。GUI 全流量没有任何开关能改变这一点。

**机制（代码原文，本仓 `HEAD 5fd3996` 已逐条复读）**
- `src/FfmpegGui/Services/FfmpegCommandBuilder.cs:21-22` —— `args.Add("-y")` 无条件，位于参数列表首位。
- `src/FfmpegGui/Services/QueueProcessor.cs:2621-2642` `TryDiscardPartialOutput(item, outputPath, existedBefore)`：`existedBefore` 分支（`:2628` 起）只追加一行 `[清理] ⚠️ 任务未成功，而输出路径在执行前已有文件（被 -y 覆盖为 {len}B 的半成品）⇒ 不擅自删除，请重新转换` 然后 `return` —— **故意不删**，且删的是"是否删尸体"，不是"内容已被清 0"这一事实。
- 覆盖预检 `QueueProcessor.cs:375-399`（`outputExistedBefore` 采样于 `:375`，判定 `:385`）**只护 CLI**：闸的实现是共享的，但 `AllowOverwriteExisting` 默认 `true`（`Models/FfmpegOptions.cs:603`），全仓只有 `CliParser.cs:811` 会把 `--no-overwrite` 写进它，而 **`src/FfmpegGui/MainWindow.xaml.cs` 全文 0 处引用该属性**（本轮 Grep 复核 `AllowOverwriteExisting|ArgumentList` = No matches）。GUI 队列提交点 `MainWindow.xaml.cs:3212-3219 AddSingleToQueue` 与 `:5910 GetOutputPath` 无 `File.Exists` 预检、无覆盖确认。
- 另有一处**静态成立但本机触达不了**的二次销毁：`QueueProcessor.cs:2399-2405` 的 ICC 兜底 fail-closed 里 `if (File.Exists(outputPath)) File.Delete(outputPath)` **不读 `existedBefore`**（CLI 面被 exit 91 前置挡住，见 §4 与 §7 手验项 5）。

**读数（一手，全部为被测件子进程真写 + 审查方自写容器判据）**
- E1：9000×9000 PNG → gif，走**产品自身心跳判死**（palettegen 阶段 120 s 无 `-progress` ⇒ 终止进程树，条目 `-124`，非人为杀进程）。原件 `200 B / sha256[:16] aea76f2a59d49d11 / OK-TRAILER / PIL 可解` ⇒ 终态 `0 B / e3b0c44298fc1c14（空文件）/ NO-GIF-HEADER / PIL-FAIL:UnidentifiedImageError`。出处 `lanes/claim-dataloss/FINDINGS.md` E1 + 该 lane 的判据汇总表。
- E4（杀宿主近似）：宿主被 `Stop-Process -Force` 后 **ffmpeg.exe PID 10468 存活继续跑**，目标在宿主被杀瞬间已是 0 B，无清理日志、无告警落盘。同上 E4 节。

### 4.1 JXL / JXR 出口标签真相：**结构不可判**（仪器侧）
