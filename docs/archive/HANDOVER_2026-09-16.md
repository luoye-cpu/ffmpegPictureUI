### 1.1 UI 可用性修复（起因：用户反馈"很多功能无法正确查看数值、显示不完整"）

**根因是三条因素叠加**，缺一不可：
1. 左侧面板固定 276px（内容可用宽仅 ~236px）
2. `<ScrollViewer>` 未设 `HorizontalScrollBarVisibility` ⇒ Avalonia 默认 **Disabled** ⇒ 超宽内容**既不滚动也不换行，直接裁剪**
3. 多处横向 `StackPanel` + 长 `TextBlock` 无 `TextWrapping`

**修复**（6 处，均为低风险：加 Wrap / 拆行 / 留余量）：

| 位置 | 问题 | 修法 |
|---|---|---|
| `:443-447` | `PngDpiBox`(72) + `png.dpi.hint`(≈200px) ≈ 276px | 拆成「数值框 + 独立提示行 + Wrap」 |
| `:496-500` | `AvifDenoiseBox`(60) + 提示(≈270px) ≈ **336px** | 同上 |
| `:529-533` | `AvifNvencAqBox`(60) + 提示(≈220px) ≈ 286px | 同上 |
| `:584-588` | **ISO 光子噪点区**（用户点名）：`JxlLosslessJpegCheck` ≈340px | CheckBox 内容改内嵌 `TextBlock` + Wrap |

| `:288-290` | 质量滑块 170+8+58 = **正好 236**（一出现滚动条即溢出） | 临时缩到 158（**后已恢复 170**，见 §1.4） |

**顺带修复遗漏窗口**：`ProgressWindow.xaml` 有 **10 处**硬编码中文（窗口标题 / Tab 头 ×2 / 表格列头 ×4 / 分析按钮等），

### 1.2 数字输入控件（组件级修复）

**用户明确指出这是"组件问题而非大小问题"**，据此定位到两条根因：

1. **口径不一致**：`NumericUpDown` 沿用 Fluent 默认字号（约 14），而项目 `TextBox` 有 11 处显式设了 `FontSize`，
   `NumericUpDown` **15 个里只有 1 个**设了
2. **固定宽度过小**：`PngDpiBox`/`TiffDpiBox` = 72px（要放 4 位数 `2400`）、`AvifDenoiseBox`/`AvifNvencAqBox` = 60px

**修复**（`Window.Styles`，项目此前**无任何全局样式**）：
- 统一 `FontSize=13` + `MinWidth=88`
- 模板内 `TextBox`：`Padding=4,0`、`MinWidth=0`（把空间让给数值）
- **微调按钮收窄 24px → 18px**（选择器 `NumericUpDown /template/ ButtonSpinner /template/ RepeatButton`，
  双层 `/template/` 语法已验证可用）
- 固定 `Width` → `MinWidth`：DPI 类 88、AVIF 类 80

### 1.3 新功能：右上角 ⚙ 二级菜单

把原先散落的 4 个按钮（🗂 缓存 / 语言 / GPU / 🌙 主题）收拢为**一个 ⚙ + `MenuFlyout`**：

```
⚙
├─ 渲染后端（手动选择 GPU，需重启生效）
│   ├─ 自动（推荐）✓ / GPU：ANGLE / D3D11 / GPU：Vulkan / CPU 软件渲染
├─ 主题      → 深色 ✓ / 浅色
├─ 语言      → 中文 ✓ / English
└─ 缓存目录  → 设置缓存目录…（标题显示当前路径）/ 打开缓存目录
```

**新增设置项** `AppSettings.RenderingMode`（`auto` / `angle` / `vulkan` / `software`），
`Program.BuildAvaloniaApp` 据此决定渲染后端顺序。

**两个设计要点**：
- **每种模式都保留 `Software` 兜底** —— GPU 初始化失败不应直接起不来
- **`RenderingMode="software"` 与 `GpuAcceleration=false` 语义同步** —— 避免「菜单说 CPU 渲染、设置里 GPU 还开着」的两处真值矛盾

**旧按钮保留但 `IsVisible="False"`** —— C# 里仍引用它们做状态同步，硬删会连带改多处逻辑。

### 1.5 双语（i18n）本地化补全 —— **今日最大工作量**

**分析结论**：机制本身是好的（`LocalizationService` 单例 + `INotifyPropertyChanged` + `RefreshVersion`，
索引器 key 缺失时**回退返回 key 名**便于发现遗漏），**问题在于大量文本绕过了本地化**。

**成果**：

| 指标 | 起始 | 最终 |
|---|---|---|
| 硬编码 XAML | 122 | **9**（剩余全是动态占位值与语言自称，按设计不迁移） |
| `<sys:String>` 中文 | 67 | **0** |
| locale key | 223 | **571**（两语言集合始终一致） |
| XAML 引用 key | 95 | **230**（全部有定义） |

**新增机制 `FillComboByLoc`**（21 个 ComboBox 接入）：
`<sys:String>中文</sys:String>` 是**元素内容**，`{ext:Loc}` 在那里**不生效** ⇒ 整类选项在英文界面下仍是中文。
改为 C# 填充 + 登记到 `_locCombos`，语言切换时 `RefreshLocCombos()` 统一刷新。

**两个必须记住的坑**：
- **默认索引必须显式传**：`ItemsSource` 为空时 XAML 的 `SelectedIndex` **已被重置为 -1**，
  不传会导致选中项丢失
- **key 顺序必须与原 XAML 逐字一致**：后端按 `SelectedIndex` 取值，顺序错位会「**界面选 A、实际跑 B**」且不报错

**覆盖范围**：主窗口 + 6 个独立窗口（ImageDetail / MetadataEditor / PresetManager / FormatFilter / Progress）

**C# 侧**：分类后迁移了 11 处**纯文本**用户可见文本（线程提示 / 媒体加载 / ICC 校验 / GPU 建议 / 队列状态）；
剩余约 39 处多为**动态拼接**（`$"队列: {n} 项"`），需带占位符的 key + `string.Format`。
C# 里还有 80 处日志、28 处异常消息 —— **多为日志，可不译**。

### 1.6 稳定性：全局异常兜底

**发现**：全仓 **28 处 `async void`** 事件处理器，其中仅约 5 个有 `try`，
且**没有任何全局异常处理** ⇒ 任一 `await` 抛异常都会让**进程无声消失**（无提示、无日志）。

**修复**（`Program.InstallGlobalExceptionHandlers()`）：
- **Avalonia `Dispatcher.UIThread.UnhandledException`** → `e.Handled = true` ⇒ **阻止崩溃**
- `AppDomain.CurrentDomain.UnhandledException`（后台线程，仅记录）
- `TaskScheduler.UnobservedTaskException`（记录 + `SetObserved()`）
- 异常同时写控制台与**缓存目录 `crash.log`**（GUI 下看不到控制台，必须落盘）

## 2. 关键机制与坑（接手必读）

| 坑 | 说明 |
|---|---|
| **`MenuFlyout` 内控件不在可视树** | XAML 的 `x:Name` **不生成字段**、`FindControl` 也找不到（**编译期报 CS0103**）。唯一入口是按钮的 `Flyout` 属性，再遍历 `Items.OfType<MenuItem>()` |
| **`<sys:String>` 不能用 `{ext:Loc}`** | 它是元素内容，标记扩展只在**属性值位置**被解析 |
| **门禁正则只匹配属性值** | 所以 `<sys:String>` 里的中文**长期隐形**（67 处一直没被发现），已单独加统计 |
| **横向 `StackPanel` 不换行** | 溢出时**既不换行也不滚动，直接裁剪**；长文本场景应改 `WrapPanel` 或拆行 |
| **`ScrollViewer` 默认不横向滚动** | Avalonia 默认 `HorizontalScrollBarVisibility=Disabled` |
| **`FillComboByLoc` 顺序即语义** | 见 §1.5 的两个坑 |
